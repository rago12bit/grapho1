Before you ship

Ship it? Ask the graph before the change goes out.

The graph the judge reads after an outage, read before one. Who feels it if this change breaks its service, whether a live incident runs through it, what changes like it did there before, what already changed on it today, and who should review it. Read-only: nothing is written.

From CI, before merge 
scripts/preflight.sh auth deploy "switch JWT validation to a rotating JWKS cache"
# exit 0: ship or review (the reasons are printed) · exit 1: hold · STRICT=1 also fails on review
curl -s -X POST localhost:8090/api/kestrel/preflight -H 'content-type: application/json' \
  -d '{"service": "auth", "kind": "deploy", "summary": "rotating JWKS cache"}'

Also an MCP tool, preflight_change, so a coding agent can ask before it opens the pull request.
